# Producer size audit — 2026-10-20

The imported producer path now yields **3.15 world studs of height for every one of the 25 playable tiers**, increased 12.5% from 2.8 after the user found the previous size too small. This is about half the height of a 5.5–6-stud avatar. Mini sizing is unchanged.

## Evidence and limits

- A read-only inspection of the named `MergeABrainrot-FirstPlayable.rbxlx` Studio found all six `CharacterModels` and nineteen `ExpansionModels` producer templates as MeshParts. Their imported dimensions match the saved asset manifests. No other Studio was inspected or modified.
- `ModelFactory.producer` normalizes imported mesh height to `3.15 / Config.PlotScale`. `WorldBuilder.placeScaled` applies `Config.PlotScale` once. The width cap does not activate for any current template.
- `tests/producer-size-cli.ps1` executes the actual ModelFactory source and the extracted WorldBuilder placement function against numeric Roblox stand-ins, using the saved imported dimensions and mesh IDs. All 25 tiers finish at 3.150 world studs, with maximum width 5.227 studs inside the 5.72-stud bay allowance. It also checks exact template selection, platform contact, a single plot-scale application, untouched source templates, unchanged Mini sizes, and nameplate clearance. The updated height assertion failed against the old 2.8-stud source before the source change, then passed.
- Upper floors are 7.15 world studs apart. The 3.15-stud body leaves 2.83 studs below the next shelf underside; the existing nameplate layout leaves 0.555 studs. The CLI asserts at least 0.5 studs for every tier using the label dimensions generated by ModelFactory. The native fixture checks the actual post-ScaleTo BillboardGui dimensions as well.
- This CLI check verifies size arithmetic and mapping, not native mesh visibility, camera perspective, animation, or perceived scale. The named Studio was in Edit mode when the read-only live-producer check was attempted, so no live avatar/model comparison was available in this audit.
- `tests/studio-producer-size.server.luau` is authored and compiles for the final native pass. It creates only private unparented fixtures, tests every imported model after real `Model:ScaleTo` and a rotated plot transform, then destroys them. It has **not been executed by this audit agent**.
- Existing live producer models are cached by WorldBuilder, so the final front-view comparison must use newly created producers after source sync. The parent agent owns that Studio sync and preview.

## Audio review, without playback changes

Existing action sounds already use different configured assets, three reusable voices, per-action cooldowns, and independent music/SFX preferences. Historical loading and lifecycle evidence is recorded in `AUDIO_PASS.md`; this audit did not repeat subjective listening or published-place permission checks.

One concrete improvement is worth prioritizing: `FeedbackAudio.note` round-robins all three voices and shares a 65 ms gate across every action. A sustained pickup stream can replace a longer merge/rebirth sound within roughly 0.3 seconds, or suppress its initial note just after a pickup. Reserve one existing voice for major actions and briefly suppress or lower pickup sounds during those cues, while keeping the existing three-voice budget. No audio source or configuration was changed here.
