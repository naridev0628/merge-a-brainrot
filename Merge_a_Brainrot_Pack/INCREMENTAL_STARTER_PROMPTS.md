# Short prompts for building one step at a time

Use these with the master build prompt in the same project chat. Each is a checkpoint instruction, not a claim that the previous step is already complete. Keep the comprehensive master prompt available to the builder.

## Start: verify setup

> Read MERGE_A_BRAINROT_ONE_SHOT_PROMPT.md and use INCREMENTAL mode. We are beginners; I use Mac and my collaborator uses Windows. Inspect the existing repository and available tools before changing anything. Begin Checkpoint 0. Give me one next action at a time. Do not generate the entire game or publish it yet.

## First playable loop

> Continue Checkpoint 1 from the working project. Build one original plot with the free starter, Minis, collect/sell/buy, the first three tiers and the approved basic UI. Follow the canonical server-owned economy and two-identical-species merge. Test the first merge and duplicate/invalid requests, then show what works and one next action.

## Full farm and rebirth

> Continue Checkpoint 2 after the first loop passes. Add all six independent plots, six original tiers, discovery and the specified rebirth. Test two-client ownership and exact reset/preserve behaviour. Keep the v1 scope; do not add trading, stealing, paid products or events.

## Save progress

> Continue Checkpoint 3. Implement the versioned profile and session-lock lifecycle, including failed load, expired/lost lease, cancelled load and ordered-save handling. Use isolated development data. Verify a real rejoin and record any unrun checks honestly.

## Review UI and presentation

> Review the draft design/features/core-loop/design.md with me before building its non-trivial UI surfaces. After the agreed design is approved, complete Checkpoint 4 across phone, tablet and desktop. Keep the game playable with empty art/audio IDs and use only documented original or authorized assets.

## Final v1 QA

> Continue Checkpoint 5. Run the relevant acceptance checklist, cap/failure checks, multiplayer test, mobile checks and production soak. Fix failures before expanding scope. Deliver actual results, remaining release blockers and one next action. Do not publish automatically.

## Optional full build

> Use FULL mode for the agreed v1 specification. Work through its checkpoints internally and deliver complete source with actual tests and known limitations. Respect any pending UI design approval; no fabricated passes, borrowed proprietary assets or automatic publishing.
