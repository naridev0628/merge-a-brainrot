# Reference organization

This folder contains an inventory, written observations, proposed captures and an original visual brief. It contains no redistributed competitor screenshots, videos, thumbnails, models or audio. The master prompt is the game specification; references help explain a design choice and never override its rules.

| File / folder | Purpose | Current status |
|---|---|---|
| `ORIGINAL_REFERENCE_INVENTORY.csv` | Every one of the 255 files in the supplied `reference.zip`, with original path, size, hash, inspection scope and disposition | Archive inventoried; selected content reviewed |
| `OBSERVED_REFERENCE_NOTES.md` | Eight directly viewed legacy images, their visible features and original adaptations | Observations completed; no Chicken Farm gameplay claim |
| `PLANNED_CAPTURE_INVENTORY.csv` | Optional Chicken Farm observation plan and the new prototype's future playtest evidence | Every row is `not_captured` |
| `incoming/` | Instructions for handling future supplied evidence | No media supplied in this replacement folder |
| `own_playtests/` | Instructions for recording the project's actual screenshots and clips | No prototype captures exist |
| `original/CHARACTER_AND_MAP_BRIEF.md` | Original primitive character silhouettes, Minis, world and presentation direction | Design brief only; assets not built |

The legacy archive has 255 files: 127 PNG, 62 WebP, 61 JPG, four MP4 and one AVIF. Its folders are `guides` (63), `ingame` (20), `ingame_clips` (4), `official` (14), `wiki` (109), `youtube_storyboards` (29) and `youtube_thumbs` (16). It contains no embedded source/license text manifest, Studio place/model or mesh-source file. Folder labels and numerical asset IDs are preserved provenance strings, not reuse permission.

All files were inventoried and hashed. Only the eight images named in the observation notes were visually reviewed; the four clips were not played. The inventory links 109 wiki image URLs from the supplied metadata using SHA-256 matches; 217 reference files also match raw research content. These matches connect source records, without establishing rights. Metadata contributors are recorded separately from rights holders, and upload dates are separate from gameplay capture dates. Remaining origin/rights/capture gaps stay explicit. An empty field means missing evidence, not a public-domain finding.

## Using the references

1. Read the master prompt's current checkpoint. Prototype with original primitive models and the six stable species IDs.
2. Consult an observation when it addresses that checkpoint: clear interaction targets, readable collection progress or feedback volume.
3. Implement the written original adaptation. Keep competitor imagery out of game textures, UI, promotional images and replacement ZIPs.
4. Capture the new project's actual result when playable, then record its build, device, date and observed result. A planned image is never a completed test.

Chicken Farm by Skandi Studios is the confirmed inspiration: [official experience page](https://www.roblox.com/games/137233438285284/Chicken-Farm). Its exact timings, recipes and UI have not been live-observed for this package. Steal a Brainrot is a broad absurd-character collection reference: [official experience page](https://www.roblox.com/games/109983668079237/Steal-a-Brainrot). These pages do not authorize importing their models or recordings.

Do not infer current competitor prices, player growth, asset rights or gameplay rules from unrelated legacy images. The new game deliberately uses two identical producers for a guaranteed next-tier merge, collectible Minis that are sold manually, and the original balance/map in the master prompt.

Production assets belong in `../assets/ASSET_MANIFEST.csv`, where provenance, permission, dependencies and review are tracked separately. None are approved by this reference folder.
