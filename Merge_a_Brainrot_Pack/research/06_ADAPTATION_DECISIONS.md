# Adaptation decisions

The master prompt takes precedence. These decisions intentionally replace legacy behaviours.

| Decision | Reason / implication |
|---|---|
| Original game, compact v1 | The user wants a simpler first project and comprehensive files |
| Incremental guidance default | One runnable checkpoint and one learner action at a time |
| Six independent player plots | Solo progression with visible collections and simple ownership boundaries |
| Six working species | Enough merge progression to test fun without a huge inherited catalog |
| Minis are goods, not producers | Avoid uncontrolled self-replication and make selling meaningful |
| Same six-second interval, higher value | Merges improve income while physical object growth stays bounded |
| Fixed Tier 1 price | Predictable early learning and simple math |
| Two identical species, guaranteed successor | Explicit user-requested mechanic; differs from legacy three-pet Luck fusion |
| No producer selling/deletion | Protect the only income source |
| Rebirth preserves discovery | Collection progress and visible achievement survive each reset |
| Integer quarter-Coin units | Exact additive 25% bonuses without per-sale rounding loss |
| Ground session-only, bag saved | Small persistence schema; explicit treatment of uncollected goods |
| No offline production in v1 | Reduce time/accounting complexity even though Chicken Farm mentions it |
| Primitive placeholders | Run immediately and keep asset rights/provenance review concrete |
| Optional original art after gameplay | No costly media pipeline before the loop works |
| Current primary docs + evidence status | Avoid treating old community or extracted config as canonical facts |
| No paid products/events/stealing/trading | Keep the first implementation focused and reviewable |

Future additions require a tested reason and a separate scope decision. Do not add premium advantages, famous meme characters, automation or more progression layers merely because the legacy reference pack contains them.
